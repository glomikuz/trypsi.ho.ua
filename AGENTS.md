# Інструкції та регламент роботи проекту trypsi.ho.ua

Цей файл містить правила та описи команд для майбутньої роботи над сайтом та його FTP-синхронізації.

## 📁 Структура проекту

- `./htdocs` — локальна папка з усім контентом веб-сайту (HTML, CSS, зображення, документи).
- `.env` — файл локальних реквізитів до FTP-сервера (не додається до Git, зберігається тільки локально).
- `.env.example` — шаблон конфігураційного файлу.
- `ftp_sync.py` — автономний Python 3 скрипт синхронізації на стандартних бібліотеках з Progress Bar та перевіркою файлів.
- `.gitignore` — виключає `.env`, `.DS_Store`, папки `backup`, тимчасові файли та логи з Git.

---

## ⚡ Як працює синхронізація (Smart Skip & Progress Bar)

1. **Розумний пропуск (Smart Skip):** Скрипт порівнює розмір віддаленого та локального файлу. Якщо файл вже є і його розмір збігається, він **не передається повторно**, виводячи позначку `⏩ [Пропущено]`.
2. **Прогрес-бар:** Для нових або змінених файлів відображається живий прогрес завантаження `⬇ Download` / `⬆ Upload` у відсотках, байтах та графічній шкалі.

---

## 🚀 Основні команди для синхронізації

### 1. Скачати останні зміни з FTP (Download / Pull)
Використовуйте цю команду перед початком редагування сайту, щоб мати актуальні файли з сервера:
```bash
python3 ftp_sync.py download
```

### 2. Вивантажити локальні зміни на FTP (Upload / Push)
Використовуйте цю команду після внесення правок, щоб опублікувати їх на сервері:
```bash
python3 ftp_sync.py upload
```

## 🔒 Правила безпеки та конфігурації

1. **Файл `.env`:**
   - Ніколи не комітити файл `.env` до версіоконтролю.
   - Пароль та логін зберігаються у `.env`.
   - Для розгортання на новому пристрої скопіюйте `.env.example` у `.env` та вкажіть реквізити.

2. **Виключення (Ignore rules):**
   - Автоматично пропускаються файли `.git`, `.env`, `.DS_Store`, папки `backup`/`backups` та тимчасові файли.

## 🔁 Два дизайни: зміни контенту — одразу в обидва

Сайт існує у двох версіях, і дані в них мають бути однакові:

| Версія | Гілка | Де живе |
|---|---|---|
| Старий дизайн (живий сайт) | `fix/test1` (робоча), `master` | на хостингу `s1.ho.ua` |
| Новий дизайн (тестова збірка) | `new-design` | тільки локально / в git |

**Правило:** будь-яку зміну контенту (тексти сторінок, нові сторінки, пункти меню, посилання, документи) спочатку вносимо в старий дизайн, а **одразу після цього — в `new-design`**, у тому ж завданні. Не можна завершувати роботу, поки зміна є лише в одній версії.

### Порядок дій
1. `python3 ftp_sync.py download` → правки в `htdocs/` на гілці старого дизайну → коміт → `python3 ftp_sync.py upload`.
2. Ті самі зміни переносимо в `new-design` (зручно через `git worktree add <tmp> new-design`, щоб не перемикати робочу папку):
   - **Контент сторінки** лежить між `<!-- content:start -->` і `<!-- content:end -->` — правимо тільки його.
   - **Меню, підвал, корисні посилання на головній, слайдер, картки** задаються в `tools/build_layout.py` (`MENU`, `EXTERNAL_LINKS`, `footer_html`, `build_home_content`). HTML-шаблон сторінок вручну не редагувати.
   - **Нова сторінка:** скопіювати HTML зі старого дизайну в `htdocs/` — скрипт сам переведе її в новий шаблон; додати її в `MENU` або `EXTRA_PARENT`.
   - **Нові файли** (docx, pdf, зображення) теж скопіювати в `htdocs/` нової гілки.
   - Після правок: `python3 tools/build_layout.py`, перевірити результат (заголовки після автоматичного виправлення КАПСУ, посилання), відкотити файли, де змінився лише `?v=` (кеш-версія CSS/JS), і закомітити.
3. **`new-design` на FTP не вивантажувати** — це тестова збірка, доки власник явно не попросить опублікувати.
