# Документ Word → сторінка сайту

**Правило:** документ ніколи не розміщується лише як посилання «Скачать». На сторінці має бути
**і посилання на файл, і сам документ, розпарсений у HTML** (текст, списки, таблиці). Зразки:
`htdocs/rozklad.html`, `htdocs/strategy.html`, `htdocs/codex.html`, `htdocs/odvit_prog.html`.

Перед початком — загальний порядок з `AGENTS.md` (download → правки → check → upload → push,
потім те саме в `new-design`).

## 1. Файл

- Скопіювати документ із `tmp/` у `htdocs/` під латинською назвою (`osvit_26-27.docx`, `codex.docx`).
  Якщо це заміна — перезаписати наявний файл з тією самою назвою.
- Upload пропускає файли того самого розміру — після upload звірити розмір живого файлу
  (`curl -sL -o /dev/null -w "%{size_download}" http://trypsi.ho.ua/<файл>`).

## 2. Розбір

```bash
python3 tools/docx2html.py htdocs/<файл>.docx --text   # огляд: [вирівнювання/N=нумерація] текст
python3 tools/docx2html.py htdocs/<файл>.docx > /tmp/doc.html
```

Конвертер (лише стандартна бібліотека; `.doc` спершу переводить у docx через macOS `textutil`) дає:
- `<p>`, списки `<ul>` (нумерація Word, абзаци з «-», переліки з «;»);
- `<h2>` — рядки КАПСОМ, «Розділ N…», «Додаток N»; `<h3>` — короткі рядки по центру всередині тексту;
- `.doc-approve` — «ЗАТВЕРДЖЕНО/ПОГОДЖЕНО/Схвалено» і текст праворуч; `.doc-sign` — підпис «Директор…»;
  `.doc-subtitle` — текст по центру;
- таблиці `.table-wrap > table.doc-table` з `colspan/rowspan`, `<thead>`, рядками `tr.total`
  («Разом/Всього») і `tr.group` (рядок на всю ширину: «1 тиждень», «Сніданок»); порожні колонки прибрано.

Результат **завжди переглянути й доредагувати**:
- прибрати титульний блок документа (назва, «ЗАТВЕРДЖУЮ», «Схвалено…») з тексту — він іде в шапку сторінки;
- прибрати порожні бланки «№ ____ від ____», службові рядки (`PAGE`, «Трипілля-2025»), старий текстовий «Зміст»;
- заголовки не вигадувати — лише ті, що є в документі.

## 3. Старий дизайн (`fix/test1`)

Замінити посилання «Скачать» у блоці `Content2Column`/`Content1Column` на:

```html
<h1 class="HTXT">Назва</h1>
<style>…</style>                       <!-- блок стилів .table-wrap/.doc-* — скопіювати з codex.html -->
<p class="doc-subtitle">…</p>           <!-- для кого / на який рік -->
<p class="doc-approve">ЗАТВЕРДЖЕНО<br>…</p>
<p class="doc-download">Завантажити: <a href="./file.docx">Назва (документ Word, 49 КБ)</a></p>
<div class="doc-body">
<ol class="doc-toc">…</ol>               <!-- зміст з якорями #r1…, якщо розділів ≥ 4 -->
…текст і таблиці…
</div>
```

- Довгі документи — зміст угорі (`<h2 id="rN">` + `ol.doc-toc`), у освітній програмі — посилання на додатки.
- Дуже великі таблиці (меню на 4 тижні) — у `<details class="doc-more"><summary>…</summary>…</details>`.
- Перевірити: усі абзаци документа є на сторінці; кількість незакритих тегів не змінилася;
  скриншот: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --window-size=1280,2400 --screenshot=/tmp/p.png http://localhost:8080/<сторінка>.html`.

## 4. Новий дизайн (`new-design`)

Той самий вміст між `<!-- content:start -->` і `<!-- content:end -->`, але:
- без `<style>` (стилі `.doc-*`, `.doc-toc`, `details.doc-more`, `tr.day-row` — у `css/style.css`);
- посилання на файл — картка: `<p class="doc"><a href="./file.docx">Назва</a> <span class="file-meta">(DOC, 49 КБ)</span></p>`;
- `tr.group` → `tr.day-row`; обгортку `div.doc-body` прибрати;
- заголовки КАПСОМ перевести у звичайний регістр вручну (з `id` build-скрипт їх не виправляє),
  римські цифри й абревіатури (КБОС, КЗ КОР) лишити;
- якщо на сторінці new-design є список архівних файлів (освітні програми, звіти) — список лишити,
  повний текст поточного документа додати нижче.
- Потім `python3 tools/build_layout.py`; new-design на FTP не вивантажувати.
